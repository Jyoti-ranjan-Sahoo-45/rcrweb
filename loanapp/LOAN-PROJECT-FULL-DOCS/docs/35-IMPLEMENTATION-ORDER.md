# 35 — Implementation Order

## Phase 0 — Repository assessment
Inspect frontend/backend/android. Record current implementation and gaps.

## Phase 1 — Foundations
Environment, database, common API shape, auth, permissions, audit base, status enums/transition service.

## Phase 2 — Loan catalog
Categories, products, requirements, eligibility configuration, customer/admin screens.

## Phase 3 — Customer application
Draft, forms, save/resume, validation, submission, application number, dashboard/list/detail.

## Phase 4 — Documents
Requirements, upload, private access, versioning, admin verification, replacement.

## Phase 5 — Internal review
Assignment, information request, eligibility/internal assessment, notes.

## Phase 6 — Decision
Approval/rejection, authority, status history, audit.

## Phase 7 — Offer
Create, preview, issue, customer review, accept/decline, expiry/versioning.

## Phase 8 — Formalities
KFS/agreement records, templates/versioning, acknowledgement, prerequisite checking.

## Phase 9 — Payment
Payment records, provider abstraction, webhook/backend verification, customer/admin states.

## Phase 10 — Disbursement
Checklist, transfer record, state updates, safe failure/retry, customer view.

## Phase 11 — Notifications
In-app, push, configured external channels.

## Phase 12 — Reports
Dashboard, reports, KPI definitions, exports.

## Phase 13 — Android integration
Shell, WebView hardening, back, file/camera, downloads, push, deep links, payment return, offline.

## Phase 14 — QA/hardening/release
Full tests, permission tests, workflow tests, responsive QA, real-device Android QA, security/performance, production config.

After every phase update changelog, progress and known issues.
