# 01 — Product Requirements Document

## Product vision
Create a digital loan platform where a customer can discover a loan, check basic eligibility, apply, upload documents, track review, receive an offer, complete required formalities, pay applicable charges, and track disbursement.

Internal teams operate the loan journey from a web admin panel.

## Customer journey
Open Website/App
→ Register/Login
→ Customer Dashboard
→ Select Loan Category
→ Select Loan Product
→ Basic Eligibility
→ Start Application
→ Personal/Business/Employment/Financial Details
→ Upload Documents
→ Review
→ Submit
→ Application Number
→ Verification
→ Internal Assessment
→ Decision
→ Loan Offer
→ Accept/Decline
→ KFS/Agreement/Confirmation
→ Applicable Payment
→ Payment Verification
→ Pre-Disbursement
→ Disbursement
→ Amount Credited

## Product goals
- Make applying easy on mobile.
- Clearly show the next action to the customer.
- Reduce manual follow-up.
- Give staff one operational view of each application.
- Preserve an auditable application history.
- Keep loan products and requirements configurable.

## Customer capabilities
- register/login/logout
- browse loan categories/products
- run basic eligibility check
- create/save/resume application
- submit application
- upload and replace required documents
- view application number and customer-friendly status
- respond to information requests
- review and accept/decline offer
- review/download allowed formal documents
- complete confirmations
- pay configured applicable charges
- view payment status
- view disbursement status
- receive notifications

## Admin capabilities
- manage loan categories/products
- manage internal users/permissions
- search/filter applications
- assign applications
- review customer information
- verify/reject documents
- request more information
- perform assessment
- approve/reject according to authority
- create/issue offers
- track acceptance/formalities
- verify payments where applicable
- manage disbursement
- view audit history and reports

## Customer experience rule
Every customer screen should make these clear:
- What is happening?
- Is anything required from me?
- What should I do next?

## Business principles
- Eligibility check is not final approval.
- Requested and approved terms can differ.
- Commercial terms must be shown clearly before acceptance.
- Applicable charges must not be hidden.
- Payment must not be described as guaranteeing approval/disbursement.
- Customer-facing status labels can be simpler than internal statuses.
